# Seismic engine availability audit — 2026-10-29

## Verdict and scope

**No: all required engines are not available.** Meaningful numerical kernels exist, but several promised engines are absent, approximations, disconnected helpers or uncommissioned runtime profiles. This is an implementation audit, separate from the still-open field and capacity acceptance gates. Missing algorithms cannot be resolved merely by adding field data or calibration.

Reviewed root commit `f6a57f7cb9c53792ceee79b3ab052caa733b9f9b` plus the existing uncommitted seismic changes. Those user changes were preserved. Read STATUS, CONTEXT, HANDOFF, SEISMIC_ACCEPTANCE and SEISMIC_EVIDENCE; inspected seismic modules, worker/API routes, dependency manifests, processing/QI frontend and numerical tests. No application fixes, deployments, job submissions, commits or pushes performed.

Status legend: **REAL** = callable implementation for the narrow numerical operation stated, not full-programme acceptance; **PARTIAL** = meaningful but incomplete/limited engine family; **STUB** = metadata/planning output standing in for the requested executable engine; **DISABLED** = intentionally uncommissioned execution profile. Explicitly absent components are listed separately rather than being called disabled UI.

## Confirmed defects and misleading completion claims

1. **SEG-Y writer is not usable for the claimed round trip.** `seismic_export.py:18–33` writes binary sample interval/count at wrong offsets; canonical binary fields remain zero. For 64 samples at 0.002 seconds the standard dt/ns/format fields read **0/0/5**. `seismic_reader.read_section` rejects the produced file with `SectionError`. The writer and SU writer also use signed `h` fields while advertising values through 65535: 40,000 samples raises `struct.error`. Nonzero TraceBlock start is not written to trace delay; arbitrary domains are accepted while units are written as seconds/microseconds. [SEG-Y rev1 specification](https://seg.org/wp-content/uploads/2025/11/seg_y_rev1.pdf).
2. **PSTM is not a full spatial migration.** `seismic_marine.py:184–223` never uses `midpoint_spacing` in the travel-time calculation. A deterministic random section with offsets 0–350 m produces bitwise-identical outputs for spacing 25 m and 2,500 m. PSDM explicitly calls this routine and rescales its axis; it is not depth migration through a velocity model.
3. **Poststack migration lacks the advertised imaging operation.** `seismic_land.py:154–172`: when start=0, the phase is identically one. The operation then only removes components outside a frequency/wavenumber cone, rather than propagating/remapping reflectors. This is more than missing field qualification.
4. **FWI gradient parameterisation is mishandled.** `AcousticSession.mass_adjoint` explicitly returns the squared-slowness gradient. `fwi_gradient_step` applies its negative normalised value directly as a relative velocity update. With m=1/v², the velocity gradient needs dm/dv=-2/v³; the current sign produces an ascent direction in velocity where clipping is inactive. No objective reevaluation/line search catches it. The prior mass-gradient Taylor test does not verify this new update wrapper. [Devito FWI formulation](https://www.devitoproject.org/examples/seismic/tutorials/03_fwi.html).
5. **RTM wrapper is labelled with the wrong imaging condition.** `seismic_rtm_work.py:9–25` applies the mass/Born adjoint to predicted-minus-observed. This is a residual gradient image, not the stated plain zero-lag wavefield-correlation imaging condition. No new RTM image-recovery fixture found.
6. **Amplitude-balancing history escapes inversion guard.** `seismic_land.amplitude_balance` normalises each trace RMS, recording method `amplitude-balance` without `amplitudePreserving=false`. `seismic_inversion.calibrated` does not reject that method. Direct audit call confirms the balanced block passes the guard with amplitude review true. This undermines the programme's calibrated-amplitude constraint.
7. **App tools do not establish persistent workflows.** `seismic_tools_api.py` accepts request arrays and returns ephemeral outputs. `seismic-qi-workspace.js` is a JSON request/result panel; examples are explicit manually loaded sample arrays. It is not the source-driven tie/QI/model workbook promised. Results are not retained as reviewed private artifacts by these endpoints. Handoff endpoint trusts caller-supplied accepted status/version values rather than verifying the actual run record; its output is a calculated descriptor, not acceptance authority.
8. **Missing libraries/integration are still real gaps.** GemPy is absent from the inspected local environment. resqpy is discoverable locally but neither GemPy nor resqpy appears in committed runtime requirements, and no corresponding seismic imports/orchestration exist. Local installation alone does not place them in API/worker containers. [resqpy EPC/HDF5 writing](https://resqpy.readthedocs.io/en/stable/tutorial/high_level_objects.html).

## Runtime availability versus source code

- Read-only Cloud Run query confirms `stratax-api-00022-yes` at 100%, with previous tagged revisions retained.
- Read environment **names only**: this API revision has no `STRATAX_SEISMIC_BATCH_PROFILE`, worker account/job or equivalent seismic configuration names. `execution_capabilities()` → `batch_available()` therefore reports unavailable under this configuration. Having analytical routes live does not mean graph jobs can dispatch.
- API requirements include NumPy/SciPy; seismic worker adds PyLops/Zarr; acoustic image separately adds Devito/compiler. No fresh image build or paid provider execution performed in this audit.
- Local module discovery: NumPy, SciPy, PyLops, Devito, resqpy, pyproj and GSTools discoverable; GemPy absent. Discovery is not a compiled/runtime test.
- Frontend publication remains unverified here; prior handoff reports live Site v15 and a credential-blocked prepared frontend. No new signed-in hosted UI claim.
