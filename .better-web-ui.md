# StrataX design context

## Design Context

This direction records the existing TerraCode/StrataX identity and the user's request for a sleeker project workspace consistent with the landing account menu.

- Audience/task: subsurface study users organizing well evidence, interpretation drafts, and project progress. Find a project and continue work without losing scientific context.
- Tone: professional, calm, precise. Clear functional labels, truthful evidence and unavailable states, and strong primary-action hierarchy.
- Palette: cool near-white `#f5f7f8`, white surfaces, deep green-gray `#172b2a`, muted green-gray `#6d7d7a`, StrataX teal `#087c73`, amber `#d2a454` for in-progress status.
- Typography: existing IBM Plex Sans for UI; IBM Plex Mono for data where useful. Match existing native ES modules and CSS; do not add a frontend framework or UI library.
- Signature: six-stage progress rails encode the existing manual workflow states. Avoid decorative fabricated plots, giant progress donuts and repeated marketing panels in the project directory.
- Current scope: gradual project setup, compact shared project switcher, real-data overview, Cloud/Local storage choice and removal of fabricated scientific displays.
- Account control: reuse the circular landing initials avatar and its accessible dropdown. No false online-status indicators or unnecessary profile-photo requests.
- Preserve working project create/edit/search/sort/favorite/duplicate/archive/Trash/restore/progress. Show storage destination and real save status; retain drafts after failures.
